# Phase 2B: UI layer rewrite (native chat, theme, webview, example)

## What
- Native chat: `ChatwootChatController` (ChangeNotifier) owns the client and the message list; `ChatwootChatView` is the one view; `ChatwootChat` (page) and `ChatwootChatDialog` are thin wrappers. Config is one `ChatwootChatOptions` value class; client events are one optional `ChatwootCallbacks`.
- Styles seam: `ChatwootChatStyle` enum (only `classic`) -> `styles/classic_style.dart` returns the flutter_chat_ui `Builders`. A new style = one file + one enum entry.
- `ChatwootChatTheme` is a `ThemeExtension` (`fromColorScheme`, `copyWith`, `lerp`, `==`); `ChatwootL10n` has only live keys.
- Webview merged into `ChatwootWidget`; pure `webview/bridge.dart`; `webview/token_store.dart`.
- Example app: three entries (native page, native dialog, web widget).

## Symptom / Root cause / Fix
**U1 script injection** (webview): user name with `'`/`"`/newline broke `set-user` or injected JS; payload was JSON in a hand-quoted JS string. Fix: the string literal is made by `jsonEncode`. Tests: round-trip, break-out attempt, mutation-checked.
**U2 cross-user conversation** : one global `cwCookie` token for every user/site. Fix: key = `conversationTokenScope(baseUrl, websiteToken, userIdentifier)` (JSON-encoded list, unforgeable), `ChatwootWidget.clearStoredConversation`, URL built with `Uri.replace` (encoded, no `//widget`). Legacy `cwCookie` entry is no longer read (not deleted).
**U14 navigation** : every URL launched, `Uri.parse` could throw, `intent:`/`file:` launchable. Fix: `decideNavigation`: widget origin allow; http/https/mailto/tel external; rest blocked; subframes http(s) only.
**U15 bridge** : blind trust, token logged, non-Map crashed. Fix: `parseBridgeMessage` sealed result, type checks, no logging.
**U16 webview lifecycle** : `setState` after await, controller built in `setState`, `dart:io` Platform, no `didUpdateWidget`, errors swallowed. Fix: `_load()` with `mounted` + generation guard, `didUpdateWidget` reload/re-inject, Android check by controller type, `onError` callback, transparent background.
**U3 late client** : `create().then(setState)` after dispose threw, was misreported as CREATE_CLIENT_FAILED and leaked the client/socket. Fix: controller disposes a client that arrives late; failure after dispose is silent.
**U4 send before ready** : `chatwootClient!` crash. Fix: sends/retries are queued per echoId and flushed once ready.
**U6 duplicates / activity as mine** : server echo of own message made a 2nd bubble; type 2/3 shown as mine. Fix: one `echoId -> serverId` alias map, upsert by key (works for either arrival order); types 2/3 skipped; author from type (0 = me, 1 = agent), not `isMine`.
**U7 O(n) per event** : `setMessages(reversed)` on every event. Fix: `insertMessage`/`updateMessage` for single events (placed by time), `setMessages` only for bulk loads.
**U8 authors/dates** : random author per sender-less message; `DateTime.parse` threw. Fix: stable `agent:<id>`/`chatwoot-agent` ids, `tryParse` fallback (keeps the first-seen time).
**U9 resolved bot** : third-party CloudFront avatar, "Bot" hard-coded, duplicates. Fix: fixed system author, no image, name from l10n, shown once until another message arrives.
**U20 attachment-only** : empty bubble. Fix: shows `l10n.attachmentLabel`; messages with neither text nor attachments are skipped.
**U5 dialog** : l10n never reached the chat, setState without mounted. Fix: one options object feeds both; header listens to the controller.
**U10 footer** : hard-coded English/colors, can't hide. Fix: `showBranding`, text from l10n, theme style.
**U11 theme** : fixed colors, ~35 dead params, global consts, no ==. Fix: ThemeExtension, derived from `ColorScheme` (dark works), spacing tokens; dead params and `CHATWOOT_*`/`NEUTRAL_*`/`PRIMARY` consts removed.
**U12 a11y** : 40dp InkWell close without label, no live region, hard-coded colors. Fix: `IconButton` (48dp, tooltip = `l10n.closeLabel`), status in `Semantics(liveRegion)`, theme colors.
**U13 l10n** : online text was "Typically replies in a few hours", unread label copy-pasted, missing keys, LTR-only padding. Fix: sane defaults, new keys (`botName`, `poweredByText`, `closeLabel`, `attachmentLabel`, `messageFailedHint`), `EdgeInsetsDirectional`.
**U17** : `@deprecated` removed from `ChatwootChat`/`ChatwootChatDialog`.
**U18 example** : `exit(0)` on iOS, `print`, `primarySwatch`, webview only. Fix: `Navigator.maybePop`, `debugPrint`, `colorSchemeSeed`, native page + dialog + web widget.
**U19** : `print` removed (debug-only `sdkLog`).

## Bugs found while testing (not in the review)
- Native chat crashed in any app using `flutter/material`: flutter_chat_ui draws with `material_ui` (separate widget set) and needs its `Material`/`Theme`/localizations. The view now supplies them.
- The send button had no icon: the theme passed `sendIcon: null`, which overrides the Composer default.
